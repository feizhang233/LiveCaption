Download → progress → verification → installed; errors retain retry. Cancel removes the temporary file. Selection only accepts verified models. Active model is unloaded before switching/deleting. No model auto-download.

Start loads the selected model, then begins actual audio ingestion. Pause stops ingestion and finalizes its tail. Stop cancels work, clears the temporary line, and releases model resources; history remains. New source clears session history explicitly in the import action. Seeking invalidates inflight results. First-confirmed timeline text remains immutable; exact overlapping boundary matches may be deduplicated. Ambiguous replay results are preserved separately and can be exported as TXT; primary SRT remains disjoint.

All four destinations use the same labels and persistent status. Disabled actions have visible explanations. User data is local; there is no cloud, analytics or artificial background keep-alive. iOS background audio belongs only to real local-media playback with system PiP. Caption history is bounded to 10,000 primary cues and 1,000 alternative records. Reaching capacity stops recognition and asks for export before clearing; earlier text is never silently deleted.

Compact iOS navigation keeps the four destinations directly accessible in the bottom tab bar. Switching destinations does not stop playback or recreate the shared session. Import and model guidance select the owning destination through the same selection state. Size-class changes preserve that selection and current captions. iOS supports iPhone and iPad with the existing bundle ID; the historical LiveCaptioniPad scheme name is retained. Native import/export panels and destructive confirmations remain system-owned. iOS model action labels have at least 44 pt height; wide action groups fall back to vertical layouts. Entering the background without starting/active local-media PiP stops recognition and releases the model; returning requires an explicit start.

iOS/iPadOS floating captions require imported local media and a verified, selected model. The visible preview establishes the system PiP source; the user explicitly starts floating captions before switching apps. Preparation and failure states remain visible. PiP uses CPU inference, with the previous acceleration preference restored when it ends; changes to acceleration are disabled during preparation and PiP. Ending PiP while backgrounded stops recognition. The system controls window placement and size. Do not offer Safari/other-app audio capture or claim background execution is guaranteed: sustained operation on a physical iPhone/iPad remains unverified.

App theme: system/light/dark. Font, color and line count apply to stage and Mac overlay. The overlay defaults to transparent text with a dark shadow; “顯示背景” opts into the shared stage background and persists separately. Native material opacity is not simulated with whole-view opacity. Higher contrast and reduced transparency override transparent caption backgrounds when a caption exists. No repeating animation.

“不顯示語氣詞” is an optional, persisted display preference, off by default. It removes only conservative standalone hesitation tokens when the recognition language is explicitly Japanese, English, French or Chinese; auto-detection and other languages are unchanged. Stage, floating captions and primary/alternative history use the same filter. Meaningful words, quoted terms and embedded word fragments are preserved. A filler-only cue produces no floating text rather than falling back to an older caption. Recorded text, timing and TXT/SRT exports remain original.

Mac floating subtitles use a borderless non-activating panel. Hover controls and the brief opening guidance reserve their space, so subtitle layout stays stable; VoiceOver keeps controls visible when click-through is off. Empty captions draw no persistent placeholder. Main live/media pages use one prominent full-width floating action with explicit ON/OFF state, plus shared options including screen/reset and width presets as alternatives to dragging. “收起主視窗” hides the control window without stopping the shared session or removing its floating captions. Closing the main window likewise leaves the menu-bar control available. The menu bar offers floating visibility, start/pause/stop, current status, filler visibility, click-through recovery and reopening the main window. App menu ⇧⌘L toggles visibility from any destination; ⌥⌘L and the main-window/menu-bar toggle recover click-through. These shortcuts are App commands, not system-wide hotkeys. Visibility, click-through and topmost changes synchronize in SessionController, including changes made from the floating controls. Hiding the panel keeps recognition running; Stop or quitting the app ends it.

Settings are grouped by purpose. General contains interface theme and shared-session guidance; caption style separates typography from background; scope owns the mode, app/site lists and browser permission action; recognition separates acceleration from runtime metrics; privacy/data owns local processing, retention and platform limits; About owns version and license information. The scope category is absent on iPad. Switching categories only changes visible controls and preserves existing settings plus the in-memory scope input, errors and permission request state. Selection is local to the settings view. Do not persist unfinished website text to disk or request permissions when merely entering a category.

Foreground scope: after explicit Start, automatically suspend outside the selected app/site set and resume on return. Manual Pause/Stop disarms automatic resume. Empty/unknown/denied web context fails closed. Scope suspension discards unconfirmed audio/results, preserves confirmed history and the loaded model, and clears the caption stage while waiting. The waiting state's primary action is 暫停自動字幕. Mode and allowlist edits save immediately; invalid domain input remains in its field with a correction message. Browser automation permission is requested only through the explicit settings button. This gates the full system mix rather than filtering by sound origin. See Docs/CaptionScope.md for scope and platform details.
